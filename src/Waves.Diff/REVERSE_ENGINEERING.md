## 结论

**Waves.Diff 是格式子集实现，不是 hpatchz.exe 的完整替代品。** 本次保持现有同步 API，增加异步 API、降低内存开销，并修复对照测试确认的兼容问题；没有把其余格式全部补齐，也没有切换下载器的原生工具调用。

## 内存与性能调整

- cover/code/extra 从整份解压数组改为各 64 KiB 的池化流式游标；支持长尺寸，不再要求这些流装入单个数组。
- 重建共用一个池化 1 MiB 数据缓冲，所有 insert gap 复用；RLE 跳过不再复制 extra 数据。
- RLE 常量加法和逐字节 extra 加法使用 `Vector<byte>`，有标量尾部和非 SIMD 回退。
- 四个区域视图分别保留逻辑位置，顺序交错读取同一差分文件时互不串位；不并发操作共享文件位置。
- 旧文件拼接通过二分查找定位，当前成员快速命中，LRU 稳态最多 16 个成员句柄、每成员 64 KiB 缓冲。成功打开新成员再淘汰，因此换入时短暂多一个句柄。
- 目录复制和校验复用一个池化 128 KiB 缓冲；压缩目录元数据直接从文件区域解压，省去整份压缩副本。
- 路径直接解码到最终数组，省去路径块和合并数组副本。拒绝绝对路径、冒号、上级目录组件及整数溢出。
- MD5 状态重置不再替换对象，校验器在结束和异常时释放。

内存边界应分开看：补丁数据流工作缓冲有界；路径、尺寸和索引元数据仍随文件数量增长，目录解压元数据仍整体加载；Zstd 原生窗口、内存池保留和系统文件缓存不属于上面的托管工作缓冲估算。

## API 与运行语义

`DiffPatcher.PatchFile`、`PatchDirectory` 签名保留。

新增 `Task PatchFileAsync(...)`、`Task PatchDirectoryAsync(...)`，参数与同步 API 对应，均接受 `Action<DiffProgress>?` 和 `CancellationToken`。

异步路径使用异步文件句柄和 Read/WriteAsync；文件头和目录元数据读取也有异步路径。cover/code/extra 游标按小块同步解码和读取，原生解压、hash、RLE 与元数据解析仍是 CPU/同步工作。异步 API 不是对整个同步入口包一层 Task.Run，也不保证每次调用立即让出线程。UI 如需把全部 CPU 工作移出 UI 线程，可在调用层统一调度。

进度回调直接发生在当前执行线程/续体上；不自动捕获 UI 上下文。预取消在目标创建前检查；操作中按块和文件边界检查取消。

原地目录冲突源写唯一临时文件，校验后替换，失败清理临时文件。整个目录更新不是事务：非冲突输出可能已写出，多文件替换阶段也没有全目录原子回滚。单文件 API 仍为直接输出，不新增原地单文件更新能力。路径字符串验证不构成对已有 symlink/junction 的文件系统隔离；调用方应提供受控目标目录。

## 验证和局限

测试工程在仓库的 `tests/Waves.Diff.Tests`，无需测试框架包，失败返回非零退出码。

最终 Release 回归：**47 passed / 0 failed**，包含原生工具对照。win-x64 NativeAOT 测试程序也完成发布与同一套 47 项回归，发布无警告。

- 16 种 HDIFF13 四流 raw/zstd 组合，同步/异步及原生输出逐字节对照。
- 空压缩类型、四 RLE 模式、回退 cover、多个 gap、大 insert、跨缓冲 extra。
- 三种全局校验的目录复制、原地交换、空/非空文件切分、全空引用及非引用空文件；与原生工具对照。
- 取消、截断、尺寸不符、varint 溢出、路径穿越、跨文件 Seek/读取、缓存淘汰及资源释放。

基准开关 `--benchmark` 在预热后三次测量，报告包括磁盘 I/O 的耗时和托管分配。池化缓冲在预热期间分配的容量、原生 Zstd 内存及峰值工作集不计入该分配数字。当前没有独立保留的修改前构建，因此不报告前后速度倍数或实测内存下降百分比。运行时会打印本机测量值；它不是所有机器或补丁形态的最优性能证明。

本机一次最终 Release 测量：600 个 insert gap 为 1.30 ms / 203,144 托管分配字节；8,000,000 字节压缩 extra 为 10.56 ms / 72,424 托管分配字节。数值为预热后三轮均值，受系统缓存和负载影响。

尚未提供真实生产 krpdiff 大包；没有据此宣称全部游戏版本补丁兼容。Windows 测试不覆盖 Unix 执行权限表现。既有文件布局限制、原生共享内存通知、SFX 和完整 CLI 行为仍需独立集成验证。
