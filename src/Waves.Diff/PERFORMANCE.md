## 一、最新优化：消除重复的 Fadler64 校验计算

### 优化原理

默认生产路径同时执行逐文件校验和整体新数据校验，两者均使用 Fadler64。此前每份新数据会被遍历计算两次。

现在保留逐文件校验，并将已验证文件的校验状态合并到整体状态。每个文件的合并耗时为常数级，无须再次遍历数据，**逐文件校验和整体校验均保留**。

对于独立初始化的后段校验状态 `(a, b)` 和字节长度 `n`，合并公式如下。所有运算按 32 位无符号整数回绕：

```text
整体.s2 += b + n × (整体.s1 − 1)
整体.s1 += a − 1
```

仅在两项校验都启用、整体校验算法为 Fadler64 时使用此优化。MD5、CRC32 和未保存整体校验的容器保持原有处理路径。尺寸与路径检查、取消、暂存发布和 Haiyu 负责的旧文件清理逻辑均未改变。

### 真实补丁对比结果

两批测试使用同一份已下载的官方补丁。每批每个版本先预热一次，再启动五次独立进程测量；各版本轮换测试顺序。优化前的 NativeAOT 程序已单独保留，测试过程离线复用样本。

下表为包含进程启动和退出的端到端耗时中位数，单位为毫秒：

| 版本 | 第一批 | 第二批 |
|---|---:|---:|
| 原版 C++ hpatchz.exe | 343.53 | 479.58 |
| 优化前 C# NativeAOT 同步版 | 315.95 | 324.97 |
| 优化后 C# NativeAOT 同步版 | **245.93** | **264.04** |
| 优化前 C# NativeAOT 异步版 | 380.92 | 430.71 |
| 优化后 C# NativeAOT 异步版 | **318.58** | **340.70** |

与上一版 C# 相比：

- 同步版耗时分别降低 **22.2% 和 18.7%**。
- 异步版耗时分别降低 **16.4% 和 20.9%**。

第二批出现较大耗时波动：异步版约 290～693 毫秒，原 exe 约 318～502 毫秒。因此，第二批算出的原版相对吞吐增幅 81.6% 不适合作为普遍性能结论。两批均显示相对上一版 C# 的明确收益；单一样本和有波动的文件系统测试，不代表所有补丁都优于 C++。

工作集仍约为同步版 **19.3 MiB**、异步版 **20.2 MiB**，原版约 **15.3 MiB**。异步版在本样本上仍慢于同步版；此次没有将异步读写替换成阻塞操作，也没有为了合并校验增加数据缓冲区。

### 正确性验证

- 两批测试中，五个版本的每次输出均通过官方文件大小和 MD5 校验。

### 测量口径

- 各版本均输出到 D 盘独立的新建空目录，不操作已安装的游戏目录。
- C# 使用 .NET 10 NativeAOT，与原 exe 一样每次启动独立进程。
- 每个版本预热一次，随后测量五次，并轮换执行顺序。
- 计时包含进程启动、退出及文件写入，不包含下载和输出 MD5 验证。
- 使用已预热的操作系统文件缓存。
- 原 exe 使用 Haiyu 的 `-f -d -k-KEY` 参数，并创建对应的命名共享内存和互斥量。
- C# 未附加进度回调；原 exe 仍承担共享内存进度更新及日志开销。因此这是贴近实际调用的端到端对比，不是完全隔离的补丁算法内核对比。
- 未调用 `Flush(true)` 强制持久化写盘，口径与通常应用操作一致。
- 工作集记录来自操作系统执行期间采样，包含运行时和原生内存，不等同于托管分配量。

此样本尚未覆盖原地更新、大量小文件、超大补丁、冷缓存及 HDIFFSF20。更广泛的性能结论仍需增加代表性样本。

## 四、历史微基准：Span、缓冲池与结构体优化

本节对比的是本轮开始前保存的 C# 程序集，不是原 C++ exe。该程序集位于：`D:/WorkSpace/HaiyuGame/Haiyu/artifacts/span-baseline/Waves.Diff.dll`。

### 改动内容

- HDIFF13 和 HDIFF19 的固定长度头部数组使用栈上 `Span`，减少堆数组分配。
- `CoverReader` 使用结构体状态机。`RleState` 保持引用类型：结构体试验未在压缩差分场景体现吞吐收益。
- 校验收尾支持 `Span`，逐文件 Fadler64 结果写入栈上空间；关闭校验时不再计算被丢弃的结果。
- Fadler64 每次处理四个查表结果，以等价加权和减少依赖链。独立标量参考测试覆盖尾部、分块、回绕、空输入和重置。
- 保留已有池化传输缓冲区、流缓冲区和基于 `Memory` 的异步批量读写。

### 测试方法与限制

运行环境为 Windows x64、.NET 10 Release。为控制即时编译变量，设置 `DOTNET_TieredCompilation=0`。

启动三个独立进程，每个文件场景预热 10 次后测量 30 次；校验场景使用固定种子的随机数据，预热 20 次后测量 50 次。完整 GC 在预热之前执行，避免缓冲池被清理后将冷租用开销错误计入某一版本。旧版本调用入口在计时外预先编译，不在每次操作时使用反射调用。

同步微基准使用 `GC.GetAllocatedBytesForCurrentThread` 记录分配量，不包含缓冲池预热分配、原生 Zstd 内存、其他线程分配或进程工作集。本测试不测量冷启动、异步吞吐和峰值内存。
